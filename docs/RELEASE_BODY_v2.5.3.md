# LNU-LibSeat v2.5.3

**低动画模式 · 默认单账号 · 跨房间默认不预选 · 版本号和帮助文档同步**

v2.5.3 是一个偏体验和发布整理的小版本。核心预约流程、WebDriver 登录、验证码识别和提交流程没有改动；本次主要新增低动画模式、调整首次打开默认配置，并让 API 局部超时提示更清楚。

> 第一次使用仍建议先开启测试模式，确认候选/方案选择正常后再执行真实预约。

## 主要更新

| 更新 | 说明 |
| --- | --- |
| 低动画模式 | 标题栏右上角新增 `动/低` 按钮。点击后会暂停动态渐变，保留当前静态渐变画面，降低窗口可见时的 CPU 占用。 |
| 默认单账号 | 干净配置首次打开默认使用单账号逐段模式。 |
| 跨房间默认关闭 | 跨房间主开关默认关闭，房间列表默认不勾选，避免首次使用自动扫描过多房间。 |
| API 局部警告 | 测试/方案摘要会显示局部座位或时间接口警告，少量超时会跳过对应数据并继续使用成功数据生成方案。 |
| 配置持久化 | 低动画开关会保存到 `config_data.json` 的 `low_animation` 字段，下次打开自动沿用。 |
| 帮助同步 | 首次帮助弹窗、README、用户指南、FAQ、配置说明和发布文档均补充了低动画模式说明。 |
| 版本同步 | 打包默认版本更新为 `v2.5.3`，界面底部版本号、启动日志和帮助标题同步显示 `v2.5.3`。 |

## 使用提示

- 如果任务结束后窗口打开仍有明显 CPU 占用，点击右上角 `动` 按钮切换为 `低`。
- 低动画模式只暂停 UI 动态渐变，不影响预约、扫描、验证码识别、WebDriver 或通知弹窗。
- 窗口最小化时系统本身通常也会减少绘制；低动画模式适合需要让窗口保持可见但又想降低占用的场景。
- 再次点击 `低` 可恢复动画。
- 跨房间需要时再开启；勾选房间越多，API 请求越多，等待时间越久。
- 其余内容请访问项目首页快速上手https://github.com/LiuDaCheng666/LNU-LibSeat/

## 推荐使用流程

1. 填写账号、校区、房间和目标时段。
2. 先开启测试模式。
3. 单账号模式下查看候选弹窗和右侧续约预览。
4. 多账号模式下查看最多 3 套完整方案。
5. 确认方案合理后关闭测试模式，再执行真实预约。
6. 跨房间选择的越多，需要等待计算的时间越久 至多50秒

## 单账号逐段注意事项

- 真实预约成功后才会保存可恢复计划。
- 测试模式的续约预览不会在重启后恢复。
- 右侧“续约计划”里的后续预案只是当前扫描结果的参考，倒计时结束后仍会重新扫描确认。
- 未开启自动取消时，找到下一段后会弹窗让你选择候选。
- 开启自动取消后，程序会按推荐候选直接取消当前预约并预约下一段，第一次使用不建议开启。

## 多账号注意事项

- 多账号按“整套方案”选择，不支持只替换某一段。
- 方案可能只使用账号 1，也可能使用 2-3 个账号。
- 如果只想待在当前房间，可优先选择当前房间方案。
- 如果更看重连续覆盖时间，可选择最长覆盖或其他房间方案。

## 关闭和恢复

单账号真实运行中关闭程序时，会保存当前预约、下一次扫描时间和后续预案。下次打开软件时：

1. 程序先弹窗展示关闭前续约计划。
2. 选择“继续计划”后，会按保存配置启动单账号真实模式。
3. 登录后会查询服务器“我的预约”。
4. 若服务器仍有有效预约，再选择继续上次计划、重新扫描或停止。
5. 选择“不管”只清理本地恢复提示，不会取消服务器上的预约。

## 🧪 功能场景举例

### 🎯 例子 1：马上找一个合适座位

现在想预约 `10:00-13:00`，不执着某一个座位：

1. 选择校区和目标房间。
2. 设置时间段 `10:00-13:00`。
3. 先开启 **测试模式** 扫描方案。
4. 关闭测试模式，确认后真实预约。

### 💺 例子 2：有心仪座位，但允许兜底

想优先坐 `185`、`186`：

1. 在优先座位里填写 `185`、`186`。
2. 策略选择 **优先座位优先**。
3. 程序会优先检查心仪座位。
4. 如果不可用，会回退到可用时间更长的座位。

### 📚 例子 3：从早坐到晚，一次约不满

目标是 `09:00-21:00`：

1. 选择 **单账号逐段**。
2. 设置提前 `30` 分钟查找下一座位。
3. 第一段例如预约到 `14:00`。
4. 到 `13:30` 自动扫描 `14:00` 之后的下一段。
5. 找到后弹窗展示下一段座位、房间和时间。
7. 用户确认后，程序取消当前预约并预约新座位。

### 🏛️ 例子 4：目标房间不理想，看看其他房间

开启 **跨房间搜索**，只勾选愿意去的房间。程序会比较当前房间和跨房间候选，如果其他房间能提供更长、更合适的时段，会提示你确认。

### 🧭 例子 5：误关程序后继续

单账号逐段运行中关闭程序，程序会保存当前预约和下一次扫描计划。下次启动后登录并查询“我的预约”，如果服务器上仍有有效预约，会让你选择继续上次计划、重新扫描或停止。

## 🔁 单账号逐段示例

假设你想从 `09:00` 学到 `21:00`，但系统无法一次预约完整时间：

1. 选择 **单账号逐段**。
2. 设置时间段 `09:00-21:00`。
3. 设置提前 `30` 分钟查找下一座位。
4. 程序先预约第一段，例如 `09:00-14:00`。
5. 到 `13:30`，程序开始扫描 `14:00` 之后的下一段。
6. 找到下一段后弹窗展示座位、房间和时间。
8. 用户确认后，程序取消当前预约并预约新座位。

---

## 🛟 关闭和恢复

单账号逐段模式运行中，如果不小心关闭程序：

- 程序会先保存当前预约、下一次扫描时间和第二段候选。
- 下次启动并登录后，会查询“我的预约”。
- 如果服务器上仍有有效预约，会让你选择：
  - 继续上次计划
  - 重新扫描
  - 停止接管

恢复时以服务器“我的预约”查询结果为准，本地状态只作为辅助。

# 常见问题

[返回文档中心](README.md)

## 第一次运行应该先做什么

先开启测试模式，确认 API 能扫描出候选或多账号方案。测试模式会弹出选择窗口并显示单账号续约预览，但不会预约、取消、换座，也不会保存为可恢复任务。

## 为什么不上传 env 到 GitHub

`env/` 是本地虚拟环境，体积大且不可移植。上传 `requirements.txt` 即可，别人运行 `run.bat` 会自动重建环境。

## 单账号模式关闭程序后会取消预约吗

通常不会。关闭程序会停止本地计时和自动换座，但服务器上已经预约成功的当前座位仍然存在。下次打开软件会先展示关闭前续约计划；选择继续后，程序会查询“我的预约”，再询问是否恢复。

## 恢复时为什么还要登录查询

本地保存的信息可能过期。服务器“我的预约”才是当前真实状态，所以恢复前必须查询。

## 为什么测试模式的续约计划重启后消失

测试模式没有真实预约，右侧续约计划只是预览，不会写入 `single_runtime_state.json`。只有真实单账号逐段预约成功后，才会保存可恢复计划。

## 多账号为什么要选择整套方案

多账号的后一段依赖前一段结束时间。如果只改某一段，后续分段可能错位。因此程序会给出最多 3 套完整方案，用户选择一整套后再执行。

## 自动取消并换座安全吗

它适合确认流程稳定后使用。第一次建议关闭该选项，让程序找到下一段后弹窗确认。

## 找到下一段后，新座位预约失败怎么办

程序会在日志中记录失败阶段。如果失败发生在当前预约已经取消后，恢复状态会保留敏感阶段，重启后仍会先查询服务器当前预约。

## 主题切换为什么要重启

当前 UI 主题样式在启动时生成。切换主题会保存偏好，重启后完整应用新主题。

## 窗口打开时 CPU 占用偏高怎么办

标题栏右上角新增了 `动/低` 按钮。点击后会进入低动画模式，暂停动态渐变并保留静态渐变画面，可以降低窗口可见时的 CPU 占用；再次点击可恢复动画。该设置会保存到 `config_data.json`。

## 跨房间扫描为什么会等更久

跨房间会在目标房间之外继续扫描你勾选的房间。勾选房间越多，座位布局和时间段 API 请求越多，等待时间也越久。新版本默认关闭跨房间，且跨房间房间默认不勾选；只勾选自己愿意接受的房间即可。

## GitHub 上传前要清理什么

确认 `config_data.json` 没有真实账号密码，不上传 `single_runtime_state.json`、`logs/`、`env/`、`build/`、`dist/`。

# LNU-LibSeat v2.6.0

**API 并发扫描 · 双进度条 · 方案列表筛选 · 超时策略优化**

v2.6.0 是一个偏”扫描速度和体验”的版本。核心登录、验证码识别和最终预约提交流程没有改变；本次主要优化 API 全量扫描速度、增加进度可视化、升级方案选择体验，并修复模式切换和弹窗稳定性问题。

> 第一次使用仍建议先开启测试模式，确认候选/方案选择正常后再执行真实预约。

## 主要更新

| 更新 | 说明 |
| --- | --- |
| API 并发扫描 | 高级设置新增 API 并发选项，可选 `1`、`5`、`10`、`15`、`20`，默认 `10`。`1` 为逐个座位扫描，速度最慢但对网络压力最小；并发越高通常越快，但根据网络环境，并发越多越容易触发超时且拿不到座位数据。 |
| 超时策略优化 | 座位时间接口取消长时间等待和二次重试。实测部分座位就是会拿不到结果，继续等待只会拖慢整体扫描进度，现在跳过当次超时继续生成方案。 |
| 双进度条 | API 扫描时弹出进度窗口，上方显示总体房间扫描进度，下方显示当前房间座位进度。直观看到当前扫描到了哪里，不再面对静止的浏览器不知所措。 |
| 方案列表升级 | 单账号候选和多账号整套方案都改为列表选择弹窗，支持筛选、排序、滚动查看和详情预览。修复之前座位多选方案抓取过少、推荐方案不合理的问题。 |
| 多账号推荐优化 | 多账号生成方案不再过度压缩候选，最多展示 50 套；跨房间开启时也会保留目标房间方案，避免推荐偏离用户优先房间。 |
| 缺口计算调整 | 开始前等待时间不再计入缺口，方案会按实际覆盖时长、当前房间、账号数量等综合排序。 |
| 模式切换修复 | 修复多账号切回单账号后重启程序，界面仍显示多账号账号列表但实际运行单账号模式的问题。现在切换后重启保持一致，无需重新手动切换。 |
| 弹窗稳定性 | 方案选择弹窗改为主界面 Qt 弹窗，跟随亮色/暗色主题，并主动置顶到前台；异常时写入 `logs/crash.log`。 |
| 驱动清理 | 增强退出和异常时的驱动清理，减少 `msedgedriver`/`chromedriver` 残留进程。 |
| 版本同步 | 打包默认版本更新为 `v2.6.0`，界面底部版本号、启动日志和帮助标题同步显示 `v2.6.0`。 |

## 关于扫描速度和超时

本版本默认 API 并发为 `10`，通常比逐个扫描快很多。你也可以在高级设置中自行选择：

- `1`：逐个扫描，速度最慢，但对网络和接口压力最小，适合排查问题。
- `5`：较稳妥，适合网络一般或频繁超时的情况。
- `10`：默认值，速度和稳定性比较均衡。
- `15` / `20`：更激进，可能更快，但根据网络环境更容易触发超时，部分座位数据可能拿不到。

即使优化后，你仍可能看到扫描末尾有几个座位超时。这通常不是进度条卡死，而是个别座位接口响应很慢或不返回。部分房间里存在显示不可用的座位——可能是临时损坏、社团专用或其他特殊状态。我无法确认这些不可用座位是否是固定的（可能以后会变化），所以没法把它们永久排除在外，只能硬着头皮扫描，跳过当次超时并继续生成方案，没有别的解决办法。

## 使用提示

- 第一次测试建议保持默认并发 `10`。
- 如果某个房间经常在最后几个座位等待很久，可以尝试把并发降到 `5` 或 `1`。
- 如果网络较好且想更快扫描多个房间，可以尝试 `15` 或 `20`，但需要接受个别座位更容易超时。
- 扫描期间请看进度窗口，不要手动点击浏览器页面。
- 多账号模式请优先看列表里的”当前房间””完整覆盖””账号最少”等筛选和排序，不必只接受第一条推荐。
- 单账号/多账号模式切换后建议手动重启一次程序，确保界面显示与实际模式一致。

## 发布前建议

1. 先用测试模式确认单账号候选列表、多账号方案列表和双进度条正常。
2. 分别测试 API 并发 `1`、`10` 和 `20`，确认日志和进度条表现符合预期。
3. 测试多账号切回单账号后重启，确认账号显示和实际模式一致。
4. 若出现闪退，检查 `logs/crash.log`，确认没有残留 `msedgedriver`/`chromedriver`。
5. 确认 `config_data.json` 不含真实账号密码后再上传仓库。
6. 不上传 `single_runtime_state.json`、`logs/`、`env/`、`build/`、`dist/`。
